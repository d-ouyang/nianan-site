# v0.2.0 —— P0-2 Hero 区

> 日期：2026-09-28。
> 截图：`docs/p0-2-hero-desktop.png`（桌面 1440×900）/ `docs/p0-2-hero-mobile.png`（390×844 降级）

## 1. 目标与范围

第一屏：ogl shader 极光背景 + 名字逐字揭示 + 滚动提示；移动端 / reduced-motion / 无 WebGL2 三路降级。不含滚动系统（P0-3）。

## 2. 实现内容

- `src/components/bits/Aurora.tsx`：reactbits Aurora（TS+TW 版）源码进仓库，标注来源
- `src/lib/capabilities.ts`：`canRunWebGL()`（reduced-motion / ≤768px / WebGL2 探测三连）+ `maxDpr()`（封顶 2）
- `src/components/sections/Hero.tsx`：背景层（Aurora 或静态辉光）+ 压暗遮罩 + 底部渐隐；名字逐字 blur+rise 揭示（motion stagger）；滚动提示走纯 CSS keyframes（不占主线程）
- 依赖新增：`ogl`、`motion`

## 3. 否掉的方案 + 代价

| 方案 | 否掉原因 | 代价 |
|---|---|---|
| 直接用 reactbits 原版 Aurora | 三个真实问题：rAF 里每帧 new Color 重算色标（每秒 ~180 个临时对象）；无离屏暂停（滚到第二屏仍满速渲染）；无降级（移动端 3x 屏全屏 shader = 掉帧+发热） | 需要自己维护这份 fork，上游更新时要手动 diff |
| three.js / R3F 做 Hero | 体积 +150KB gzip， ogl 20KB 级就够 | 用户已拍板：R3F 版后续单独做一版对比，两版实测再定 |
| 文字动效用 GSAP SplitText | 为一个 stagger 引入整套 GSAP 不值；P0-3 才需要 GSAP | motion 的 stagger 完全覆盖当前需求 |
| 中途 resize 重新判断降级 | 重建 WebGL 上下文的代价远大于收益 | 加载时定一次，拉伸窗口不切换渲染路径 |

## 4. 踩坑与修复

- 原版 Aurora 的 `uColorStops` 依赖用数组直接传进 useEffect 依赖 → 引用每次渲染都变，会无限重建 WebGL 上下文。改成 `stopsKey = colorStops.join(',')` 作依赖。
- raw.githubusercontent.com 拉源码超时 → 改走 `api.github.com` contents 接口取 base64 解码。

## 5. 验收结果

| 指标 | 预算 | 实测 |
|---|---|---|
| 首屏 JS gzip | < 200KB | **126.75KB**（+56.8KB：ogl + motion） |
| LCP | < 2.5s | **1332ms**（playwright，swiftshader） |
| FPS | 60fps | **61**（swiftshader 软渲染下，说明无结构性掉帧；真机 GPU 只会更高） |
| WebGL canvas 数 | ≤ 1 | 1 |
| 移动端降级 | 必须降级 | 390×844 下无 canvas，静态辉光正常 |
| 控制台 | 无错误 | 0 error（桌面 + 移动） |
| 名字逐字动画 | 三字全部可见 | opacity 全部 1 |

离屏暂停（IntersectionObserver）已实现；rAF 内部状态无法从外部直接断言，靠标准 API 行为保证。

## 6. 遗留与下一步

- motion 全量引入占 ~50KB；若 P0-4 后逼近预算，换 `m` + `LazyMotion`（预计省 ~20KB）
- 下一步：P0-3 滚动与导航系统（Lenis + GSAP ScrollTrigger + Dock）
