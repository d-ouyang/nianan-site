# v0.3.0 —— P0-3 滚动与导航系统

> 日期：2026-09-29。
> 截图：`docs/p0-3-desktop.png`（桌面，锚定到作品区）/ `docs/p0-3-mobile.png`（移动端 Dock）

## 1. 目标与范围

Lenis 惯性滚动 + GSAP ScrollTrigger 对接 + 底部 Dock 导航 + 右侧滚动进度条 + URL hash 同步。
内容区仍是占位（`Stub`），P0-4 替换；导航只认 `SECTIONS` 注册表，换内容不用改导航。

## 2. 实现内容

- `src/lib/sections.ts`：区块注册表，导航的唯一数据源（Dock 高亮 / 进度 / hash / 锚点全部由它派生）
- `src/hooks/useScrollSystem.ts`：滚动系统
  - Lenis ↔ GSAP ticker 对接（`lenis.on('scroll', ScrollTrigger.update)` + `gsap.ticker.add` + `lagSmoothing(0)`）
  - ScrollTrigger 判当前区块（`top center` → `bottom center`）
  - hash 用 `replaceState` 同步，不用 `location.hash`
  - 带 hash 直进时补一次 `scrollTo(immediate)`
  - GSAP / Lenis 全部动态 import
- `src/components/ui/Dock.tsx`：底部悬浮导航，motion `layoutId` 滑动指示器
- `src/components/ui/ScrollProgress.tsx`：右侧进度条，`useSpring` 包裹 `scrollYProgress`
- `src/components/sections/Stub.tsx`：占位区块
- `vite.config.ts`：函数式 `manualChunks` 按库拆包

## 3. 否掉的方案 + 代价

| 方案 | 否掉原因 | 代价 |
|---|---|---|
| IntersectionObserver 判区块 | P0-4 滚动叙事 / P1-6 路径绘制都要用 ScrollTrigger，一套滚动观测比两套好维护 | 为「判当前区块」引入了 45KB 的 gsap；靠动态 import 抵消（见下） |
| GSAP + Lenis 静态引入 | 首屏 JS 会到 183KB，逼近 200KB 预算；而没人一进页面就滚动 | 加载完成前点 Dock 锚点会回落到原生跳转（不丝滑但可用）；多一层异步初始化与 disposed 守卫 |
| 对象式 `manualChunks` | 只匹配包入口，`react-dom/client` 这类子路径漏掉，react-dom 仍混在业务 chunk 里 | 函数式写法更长，且新增依赖要记得归类 |
| Dock 用 `left-1/2 -translate-x-1/2` 居中 | 见 §4 坑 2 | 改用 `inset-x-0 + flex justify-center`，多一层 DOM |
| GSAP 留到 P0-4 再装 | 用户已拍板 P0-3 就打通 ScrollTrigger，且区块判定确实要它 | 本期就用上了，不算浪费 |

## 4. 踩坑与修复

1. **Vite 重优化依赖被沙箱拦死**：lockfile 变化触发 re-optimize，要删 `node_modules/.vite/deps`（52 个条目 > 沙箱 50 的批量删除阈值），直接起不了 dev server。修法：按用户新规跳过沙箱执行 `rm -rf node_modules/.vite`。
2. **`fixed left-1/2 -translate-x-1/2` 的宽度陷阱**：fixed 元素的可用宽度被算成视口的一半，Dock 被压到 210px，中文标签竖排断行（「首页」拆成上下两个字）。修法：`inset-x-0 + flex justify-center` + `whitespace-nowrap`。
3. **验证脚本给了假绿灯**：最初只断言「是否溢出视口」，而 Dock 被压扁时宽度反而更小，判定为「没溢出」= 通过。修法：改断言「按钮是否被压缩到换行 / 内容是否被截断」（`scrollWidth > clientWidth`）+ 按钮高度必须单行。**看起来验 A 实际验 B 的断言比失败更危险。**
4. **reduced-motion 下整条导航是死的**：最初把 Lenis 初始化和区块判定写在同一个 effect 里，而该 effect 开头 `if (prefersReducedMotion()) return`，导致这类用户 Dock 不高亮、hash 不更新。修法：拆成两个 effect —— Lenis 按需跳过，区块判定永远执行（它跟动效无关）。

## 5. 验收结果

| 项 | 判据 | 实测 |
|---|---|---|
| 锚点跳转 | 目标区块顶对齐视口顶 | `#projects` top = **0px** |
| 深链接 | 带 hash 直进应定位而非停在顶部 | `#skills` top = **0px** |
| hash 同步 | 滚动/点击后更新 | `#hero` → `#projects` → `#contact` |
| Dock 高亮跟随 | 与当前区块一致 | 首页 → 作品 → 联系 |
| 进度条 | 顶 0 / 中 0.5±/ 底 1 | **0.000 → 0.600 → 1.000** |
| 锚点后高亮 | 点击后立即更新 | ✅ |
| Dock 布局 | 三档视口标签不换行不截断 | 390px 按钮高 29px / 768·1440 为 31px，截断项 0，无溢出 |
| reduced-motion | Lenis 不接管、锚点仍准、hash 仍同步 | 全部 ✅ |

| 运行期 FPS | 无结构性掉帧 | 121 |
| 控制台 | 无错误 | 0 |
