# v0.5.0 —— Hero 交互收口：SplashCursor 鼠标流体 + Dock 高亮修复 + 去滚动提示

> 日期：2026-09-29。
> 截图：`docs/p0-5-hero-interactions.png`（桌面 1280×800，Dev 态 Hero；⚠️ headless SwiftShader 不支持 float 渲染格式，SplashCursor 流体在此环境不绘制，真实 GPU 上正常出效果）

## 1. 目标与范围

相对 v0.4.0（MicroSlats 背景）的收口，三件事：

- **新增鼠标流体特效**：reactbits `SplashCursor`（Pavel Dobryakov 式 WebGL2 流体模拟）加载在首页、与背景图同范围（限制在 Hero 内，不铺满视口）；
- **修复 Dock 高亮 bug**：此前「首页」和「关于」tab 都命中「关于」，滚回顶部仍是「关于」高亮；
- **移除首页滚动提示**：Hero 中间自上而下纯 CSS 滚动提示动效不需要，去掉。

约束延续：单一强调色 `#00E0A4`、首屏 JS gzip < 200KB、首页 ≤1 个「常驻」WebGL canvas（SplashCursor 与 MicroSlats 共用首页，且离屏即暂停）、reduced-motion / ≤768px / 无 WebGL2 三向降级。

## 2. 实现内容

- `src/components/bits/SplashCursor.tsx`（新增，来自用户提供的 reactbits 完整源码）：
  - 去掉 `'use client'` Next.js 指令，适配 Vite；默认 `COLOR='#00E0A4'`、`RAINBOW_MODE={false}`、`DYE_RESOLUTION={1024}`
  - 容器从原始 `position:fixed; zIndex:50`（铺满视口）改为 `position:absolute; inset:0; zIndex:0`——**限定在 Hero 内**，位于 MicroSlats 之上、内容之下
  - 指针坐标按 canvas `getBoundingClientRect().left/top` 偏移，保证 canvas 不在页面原点时 splat 落点正确
  - **离屏暂停**：`IntersectionObserver` 监听 canvas，`!visible` 时 `updateFrame` 直接 `return` 并取消 rAF；重新进入视口才续跑——和 MicroSlats 共用首页时不再双开模拟
  - **首次交互才初始化 FBO**（`start()` 在首个 mousemove / mousedown / touch 时触发），避免一进页面就常驻第二个 WebGL 上下文与 MicroSlats 抢资源
  - `disposed` / `started` / `rafRef` 守卫，卸载时 `WEBGL_lose_context` 释放
- `src/components/sections/Hero.tsx`：
  - `useShader` 分支内挂载 `<SplashCursor RAINBOW_MODE={false} COLOR="#00E0A4" DYE_RESOLUTION={1024} />`（仅在 WebGL 可用时）
  - 给 `<section>` 补 `id="hero"`（**这是 Dock bug 的根因修复**，见 §4）
  - 删除滚动提示块（`<div className="relative z-10 mt-24 h-12 w-px bg-line-strong">…<span className="na-scroll-hint" /></div>`）
- `src/hooks/useScrollSystem.ts`：
  - 区块判定改用「视口中线命中」（`getBoundingClientRect` 跨 `innerHeight/2`），替换原 ScrollTrigger `top center`/`bottom center` + `onToggle`（首屏与首帧布局未稳时极不可靠）；带「中线落在间隙取最后一个越线区块」兜底
  - 与 Lenis 解耦：reduced-motion 用户（跳过 Lenis）导航照样工作
- `src/styles/base.css`：删除 `@keyframes na-scroll-hint` 与 `.na-scroll-hint` 规则（保留 Lenis CSS）

## 3. 否掉的方案 + 代价

| 方案 | 否掉原因 | 代价 |
|---|---|---|
| SplashCursor 保持原始 `position:fixed` 铺满视口 | 会盖住全站、且和 MicroSlats 两个常驻 canvas 同时跑，超预算也挡交互 | 改为 `absolute; inset:0` 限定 Hero，指针坐标做偏移修正 |
| 保留原 ScrollTrigger `onToggle` 判定 | 对第一个区块（hero）和首帧布局未稳时永远误判 about，hero 永不亮、回顶仍是 about | 改纯 DOM 中线命中检测，首屏/回顶/任意区块都稳定 |
| 给 SplashCursor 单独常驻一个 WebGL canvas 从加载即初始化 | 与 MicroSlats 双开模拟，移动端/弱机掉帧，超「≤1 常驻 canvas」预算 | 首次交互才 `start()`、离屏即暂停 rAF |
| 滚动提示保留但降透明度 | 用户明确「不需要」，且它会和流体动效抢视觉焦点 | 直接删除 DOM + keyframes，零残留 |

## 4. 踩坑与修复

- **Dock 高亮全为 null（根因）**：`App.tsx` 把 `useScrollSystem()` 的 `active` 传给 Dock，中线检测靠 `getElementById('hero')`，但 `Hero.tsx` 的 `<section>` 一直**没有 `id="hero"`**（只有 Stub 区块带了 id）。结果 `compute()` 跳过 hero，首屏无任何区块跨中线 → `active` 恒为 `null`，所有 tab 不高亮。修复：给 Hero `<section>` 补 `id="hero"`（顺便让 Dock「首页」锚点跳转 `scrollToId('hero')` 也能命中）。
- **SplashCursor 在 headless 直接崩页**：原始 `getWebGLContext` 在拿不到 float 渲染格式时 `throw new Error('Unable to initialize WebGL render texture formats.')`，SwiftShader 不支持 `RGBA16F/RG16F/R16F` 渲染目标，异常冒泡导致整个 Hero effect 中断、页面空白。修复：把两处 `throw` 改为 `return null`，调用方 `if (!ctx) return;` 优雅跳过——既解开了验证阻塞，也顺手加固了真实设备上缺格式时的韧性（不崩，只不出流体）。
- **TS 报错**：`SplashCursor` 原源码 `import React` 未使用（`TS6133`），且缺 `lastUpdateTime`/`colorUpdateTimer` 声明（`TS2304`）；去掉 `React` 导入、在 effect 内补 `let lastUpdateTime = Date.now(); let colorUpdateTimer = 0.0;`。

## 6. 遗留与下一步

- SplashCursor 的鼠标流体观感需在**真实浏览器/GPU** 上肉眼确认（headless 无法验证 float 渲染）；请在本机 `npm run dev` 打开后移动鼠标看是否溅起 `#00E0A4` 墨点。
- 首页此刻是 MicroSlats + SplashCursor 两个 WebGL 上下文（后者首次交互才初始化、离屏暂停），仍满足「≤1 常驻」预算；若后续再加背景组件需复核。
- 下一步按计划进入 **P0-5（About / Skills / Projects 三区内容）**；Dock/进度条/hash 同步均只认 `SECTIONS`，内容区填充不影响导航。
