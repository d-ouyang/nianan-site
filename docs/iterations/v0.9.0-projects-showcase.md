# v0.9.0 · 项目区深度展示

> 关联版本：0.9.0（MINOR，新功能）
> 一句话结论：**项目区从一张「nianan.site 自述卡」改为两个主力项目的深度展示——点开卡片可见技术栈、规模数字、亮点难点、逐版迭代与量化收益，全部数字可溯源。**

## 1. 背景

v0.8.0 的项目区只有一张个人网站自述卡。两个真正撑简历的项目——企业级 RAG 智能问答系统（个人全栈项目）和锅圈商城多端小程序（公司项目）——没有位置。用户要求把这两个项目补进去，且要体现亮点与难点：RAG 侧要说清技术栈、迭代改动与前后量化收益、0→1 部署与自动化流程；锅圈侧挑最要紧的业务复杂度与优化细节说（多端架构、AI 点单、社交拼单、分包与 easycom 等）。

## 2. 设计决策

- **卡片折叠，不堆长文。** 两个项目各一张卡，收起态只留 meta / 标题 / 一段摘要 / 标签，点开才展开四个区块（技术栈、规模数字、亮点与难点、关键迭代与量化收益）。展开的卡片 `lg:col-span-2` 独占一行，另一张自然落到下一行，网格不被撑坏。
- **数据全部落在 `profile.ts`，组件只排版。** 沿用既有约定：`projects` 升级为带 `stack / metrics / highlights / iterations` 的结构化数组，后续补项目只改数据文件，不碰组件。正文里的 `**加粗**` 由一个小渲染器处理，不引 Markdown 依赖。
- **数字必须可溯源。** RAG 的测试数（1376）、文档/切片数（35/90）、评测基线（recall@5 0.8944 / recall@10 0.9389 / MRR@10 0.8889 / 拒答 10/10）、混合检索 A/B（+4.45pp 但 recall@20 判据不过 → 默认关）全部来自 rag-qa-system 的 `docs/RELEASES.md` 与 `docs/PLAN-v3.0.0.md`；锅圈的分支数（89）、源文件数（1269）、条件编译数（649）、拆出主包组件数（57）来自仓库实测（`git branch -a | wc -l`、`grep -c '#ifdef'`）。
- **锅圈只挑最要紧的说。** 按用户要求以业务复杂度和优化为主线：多分支 + 条件编译双轨架构、支付登录四端封装、两级异步分包、自研 Vite 插件自动化 componentPlaceholder + easycom、AI 点单、一起吃拼单、CMS 配置化渲染。商品浏览 / 加购 / 拼团秒杀接龙 / 结算 / 优惠券 / 积分 / 会员等级作为业务面在摘要中点名，不逐项展开。
- **视觉不破既有体系。** 全部用令牌色（`text-accent` / `text-muted` / `text-faint` / `bg-canvas`），强调色仍只有 `#00E0A4` 一个色相；卡片继续 `rounded-2xl bg-canvas/35 backdrop-blur-sm`，与技能文件夹、经历卡片同一质感。

## 3. 改动

- `src/content/profile.ts`：`projects` 数组重写——新增 `stack / metrics / highlights / iterations` 字段与两个项目的完整数据（约 110 行内容）。
- `src/components/sections/Projects.tsx`：重写为可展开卡片。`Bold` 小组件处理 `**粗体**`；`DetailBlock` 统一四个区块的眉题与间距；迭代行在窄屏堆叠、宽屏三栏（版本 / 标题 / 收益）。
- `package.json`：版本 0.8.0 → 0.9.0。
- `docs/CHANGELOG.md`、`docs/PLAN.md`、本文件。
