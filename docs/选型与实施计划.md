# 个人主页（nianan.site）技术选型与实施计划

> 状态：待拍板。本文只做选型论证与计划，未写任何业务代码。
> 关联项目：`rag-qa-system` 后续部署在 `qa.nianan.site`，与本文共用同一台服务器与同一个 443 入口。

---

## 0. 结论先行

**推荐：Vite 7 + React 19 + TypeScript + Tailwind CSS v4，动效直接用 reactbits.dev 的源码组件（ogl / GSAP / motion / Lenis），产物为纯静态，nginx 托管。**

三条理由，按权重排序：

1. **动效组件供给** —— reactbits 210+ 组件，是三个站里唯一超过 200 的，且是「源头」：vue-bits / sveltebits 是它的移植版，新组件先在 reactbits 出现。你要「很酷炫」，组件池的深度直接决定天花板。
2. **内存约束**（硬约束，见 §1）—— 服务器 4C4G 已被 RAG 全栈排满，个人主页必须是零常驻进程的纯静态站。这条直接排除 Next.js SSR / Nuxt SSR，也顺带把「框架选型」的权重从「生态」降到「构建产物够不够小」。
3. **独立性** —— 个人主页与 `rag-qa-system` 的前端没有一行代码要共享。各自独立仓库、独立构建，互不干扰；反过来若强行统一成 Vue，只是换来「看着一致」，代价是动效组件少 80 个。

明确不推荐的：

| 否掉的选项 | 否掉的原因 |
|---|---|
| Next.js（SSR / App Router） | 需要常驻 Node 进程（150–300MB），4C4G 上加不动；本页没有服务端渲染需求。用 `output:export` 又等于一个大号 Vite |
| Nuxt 3 | 同上。且 vue-bits 组件数只有 130+ |
| SvelteKit / Svelte 5 | sveltebits 仅 371 star、更新最慢，组件库风险最高（哪天停更就断供） |
| Astro + islands | 生态正确但收益错位：Astro 的卖点是「内容站 SEO + 零 JS」，而本页核心是动效，几乎每个区块都是交互岛，Astro 的优势吃不到，反而多一层集成成本 |
| 纯手写 Canvas/WebGL 全部动效 |  achievable 但时间成本翻几倍；先用现成组件铺满，再对 Hero 单独定制，ROI 更合理 |

## 1. 硬约束（先说不能做什么）

这四条决定了后面所有选择，先摆出来。

### 1.1 内存：4C4G 已经排满

`rag-qa-system` 上线后的常驻占用（PLAN §11.1 实测）：backend 1.8–2.2G + worker 0.5–0.7G + MySQL 0.35–0.45G + Redis + Chroma。剩余空间不足以再养一个 Node 进程。

> **推论：个人主页的运行时成本必须等于 0。** 静态文件由 nginx 直出，不跑 SSR、不跑 BFF、不跑 node server。

### 1.2 备案：ICP 备案中，域名暂时不能指到国内服务器

腾讯云轻量（上海）在备案完成前，80/443 上的域名访问会被拦。

对策：
- **开发期**：本地 `pnpm dev` 为主；要给别人看就先发 Vercel 或 Cloudflare Pages（免费、自动 HTTPS、一条命令），拿到一个能访问的预览链接。
- **证书**：已在 `rag-qa-system/docs/部署方案-子域名.md` 定好 —— **certbot 通配符 `*.nianan.site` + DNS-01 验证**（腾讯云 DNS API）。DNS 验证不占 80 端口，绕开 HTTP-01 在备案期失败的问题，且一张证书覆盖全部子域、自动续期。
- 备案通过后一次性切到自有机房。子域随主域备案一并覆盖，不用单独备案。

### 1.3 端口：根域名与 qa 子域共存

⚠️ 这一节**不是新决策**，是直接沿用 `rag-qa-system/docs/部署方案-子域名.md`（2026-09-28 已定）。本文个人主页部分必须长在那套方案上，不要另起一套。

统一入口是一台**边缘 nginx**（唯一对公 80/443，持通配符证书），按 `server_name` 分流：

```
                         边缘 nginx（:443，唯一对外，docker network 内）
                                    │
            ┌───────────────────────┴───────────────────────┐
       nianan.site                                     qa.nianan.site
       root /var/www/personal                          proxy_pass http://qa-frontend:80
       （纯静态，本文项目）                              （rag-qa-system frontend 容器）
```

两个要点：
- 静态目录是 **`/var/www/personal`**（对齐既有方案的目录规划，不是新起名）。
- 边缘 nginx 与 QA 容器**同 docker network**，反代走容器名 `qa-frontend:80`，不写死 `127.0.0.1:8080`。

`rag-qa-system` 那边的 P1-7（配 TLS）正好可以一起收口。

### 1.4 移动端：WebGL 背景在低端机掉帧 + 耗电

ogl / three 那类全屏 shader 背景在移动端是「好看但烫手」。必须有降级路径（§5.4）。

## 2. 三个参考站实测对比

2026-09-28 实抓首页数据：

| | [reactbits.dev](https://reactbits.dev/) | [vue-bits.dev](https://vue-bits.dev/) | [sveltebits.xyz](https://sveltebits.xyz/) |
|---|---|---|---|
| 组件数 | **210+** | 130+ | 130+ |
| GitHub Stars | **48.2K** | 4.5K | 371 |
| 技术栈 | React + TS + Tailwind | Vue 3 + TS + Tailwind | Svelte 5 + TS + Tailwind |
| 分类数 | **5**（含最新 Micro-interactions） | 5 | 4 |
| 安装方式 | `npx shadcn add @react-bits/X-TS-TW` | `npx jsrepo add <url>` / shadcn | — |
| 风味可选 | JS/TS × CSS/Tailwind **四种** | 仅 TS + Tailwind | 仅 TS + Tailwind |
| 底层依赖 | ogl、GSAP、motion | ogl、GSAP | ogl、GSAP |
| 生态位 | 源头，最先出新组件 | 移植版，滞后 | 移植版，最慢 |

**判读**：三个站是同一套设计的三语言移植（首页文案、示例组件 `ColorBends`、分类结构几乎一致）。选哪个本质是选语言生态，不是选设计。reactbits 的 star 数是 vue-bits 的 10 倍、sveltebits 的 130 倍 —— 对个人项目来说，这个差距决定了「半年后还能不能拿到新组件」。

**注意**：reactbits 有 Pro（付费，含页面块与 Next.js 模板）。开源部分 210+ 组件对个人主页完全够用，**不需要买 Pro**。

## 3. 技术栈清单

### 3.1 核心

| 层 | 选择 | 说明 |
|---|---|---|
| 构建 | **Vite 7** | 静态产物、冷启动快 |
| 框架 | **React 19** | 组件池最大；你本身也熟悉 |
| 语言 | TypeScript（strict） | bits 组件全是 TS |
| 样式 | **Tailwind CSS v4**（`@tailwindcss/vite`） | CSS-first 配置，构建比 v3 快 |
| 路由 | React Router v7（或单页锚点，见 §4.1） | 见下 |

⚠️ **Tailwind v4 的一个已知摩擦**：部分 bits 组件文档里的示例假设了 `tailwind.config.js` 的 `extend`（自定义 keyframes / 颜色）。v4 没有这个文件，需要把对应项写进 CSS 的 `@theme`。实践上 bits 组件绝大多数只用工具类 + 行内样式，真正需要迁的量很小，但**每加一个组件都要本地跑一遍确认动效生效**。若嫌麻烦，退到 Tailwind v3.4 也能跑，代价是构建慢一点。

### 3.2 动效依赖（按需引入，不要一次全装）

| 用途 | 库 | 备注 |
|---|---|---|
| 布局/进入/手势动画 | **motion**（framer-motion v12 的新名） | React 19 兼容 |
| 滚动叙事 | **GSAP 3.13 + ScrollTrigger** | 3.13 起全部插件免费（含 SplitText） |
| 惯性平滑滚动 | **Lenis** | 与 ScrollTrigger 需手动对接 `scrollerProxy` |
| WebGL 背景 | **ogl**（reactbits 默认） | 比 three.js 轻很多（~20KB），够用 |
| 3D（可选，仅 Hero） | three.js + R3F | 体积大（gzip ~150KB+），非必要不上 |
| 图标 | lucide-react | 树摇友好 |

### 3.3 字体（中文站最容易踩的坑）

**不要给中文上 Web Font。** 一个完整中文字体 3–5MB，会直接把 LCP 打死。

- 中文：系统字体栈 —— `-apple-system, "PingFang SC", "HarmonyOS Sans SC", "Noto Sans SC", sans-serif`
- 英文/数字/标题：可变字体一份（Geist / Space Grotesk / Inter Variable 三选一），`woff2` 子集化后 ~30–60KB
- 代码/代号：Geist Mono 或 JetBrains Mono

## 4. 视觉与布局方案

### 4.1 页面形态：单页 scroll-telling

个人主页内容量小、叙事性强，**单页 + 分区锚点**比多页路由更炫（动效连贯、滚动叙事成立）。博客/项目详情这类增量内容以后再开 `/blog/:slug` 子路由。

### 4.2 视觉基调

按你一贯的审美（暗色、PostHog/Sentry 那类 dashboard 质感）：

- 底色近黑（`#0A0A0B` 一类），卡片用半透明玻璃 + 1px 冷色描边
- 主色一个（青/紫二选一），强调色只用于 hover 与关键数字，**不要满屏彩虹**
- 背景层：细网格 + 局部辉光（radial-gradient），滚动时视差
- 卡片 hover：BorderGlow / Magic Card 那类「光跟随鼠标」的微交互

### 4.3 分区结构

| # | 区块 | 主打动效 | reactbits 组件 |
|---|---|---|---|
| 1 | **Hero** | 全屏 WebGL 背景 + 名字逐字揭示 + 滚动提示 | Aurora / ColorBends / Beams + SplitText / ShinyText |
| 2 | **About** | 滚动进入的分行揭示、关键词高亮 | BlurText、ScrollReveal |
| 3 | **Skills** | Bento Grid，hover 发光倾斜 | Magic Card / BorderGlow / TiltedCard |
| 4 | **Projects** | 卡片列表，hover 展开预览、磁吸 | Dock、Magnet、SpotlightCard |
| 5 | **Timeline** | 滚动驱动 SVG 路径绘制 | GSAP ScrollTrigger + drawSVG 手写 |
| 6 | **Contact** | 社交链接磁吸 + 光标拖尾 | Magnet Lines、Splash Cursor |

导航：底部居中 **Dock**（reactbits Components/Dock）+ 右侧滚动进度条。

### 4.4 性能预算（写进验收，不是写进愿望）

| 指标 | 上限 |
|---|---|
| 首屏 JS（gzip） | **< 200KB** |
| LCP | **< 2.5s**（4G 模拟） |
| 同时运行的 WebGL canvas | **≤ 1 个** |
| 常驻 requestAnimationFrame 循环 | 离屏时暂停（`IntersectionObserver`） |

## 5. 部署方案

### 5.1 目录与发布

沿用既有方案的目录规划（`/opt/edge` 放边缘 nginx 配置与证书，`/var/www/personal` 放个人站）：

```
本地：pnpm build → dist/
服务器：/var/www/personal/            （dist 内容）
发布：rsync -avz --delete dist/ user@host:/var/www/personal/
```

一次 `rsync` 就完成发布，原子性靠「先传后切」：传到 `/var/www/personal.new` 再 `mv` 覆盖，避免发布中途访问到半份文件。

### 5.2 nginx server 块（根域名部分）

这段配置挂在**边缘 nginx**，与 `qa.nianan.site` 的 server 块并列，共用同一张通配符证书：

```nginx
server {
    listen 443 ssl http2;
    server_name nianan.site www.nianan.site;

    # 通配符证书由 certbot 签发，与 qa 子域共用同一份 ssl_certificate
    ssl_certificate     /etc/letsencrypt/live/nianan.site/fullchain.pem;
    ssl_certificate_key /etc/letsencrypt/live/nianan.site/privkey.pem;

    root /var/www/personal;
    index index.html;

    gzip on;
    gzip_min_length 1024;
    gzip_types text/css application/javascript image/svg+xml;

    # 带 hash 的构建产物可以长缓存；index.html 必须禁缓存，否则改版不生效
    location /assets/ { expires 1y; add_header Cache-Control "public, immutable"; }
    location = /index.html { add_header Cache-Control "no-store"; }

    location / { try_files $uri $uri/ /index.html; }
}

server {
    listen 80;
    server_name nianan.site www.nianan.site;
    return 301 https://$host$request_uri;
}
```

### 5.3 预览环境

备案完成前用 **Vercel** 或 **Cloudflare Pages**：`pnpm build` 产物直传，自动 HTTPS，一条命令出链接。正式切自有机房时只需把 DNS A 记录改过去。

### 5.4 移动端降级（必做）

- `@media (max-width: 768px)`：Hero 的 WebGL 背景换成静态渐变 / 轻量 CSS 动效
- `@media (prefers-reduced-motion: reduce)`：全部动效降级为无动画直出
- 检测 `deviceMemory` / 首帧耗时，过低则不再初始化 shader

## 7. 风险与对策

| 风险 | 概率 | 对策 |
|---|---|---|
| Tailwind v4 与 bits 组件的配置摩擦 | 中 | 每加一个组件本地验证；真卡住就退 v3.4（成本仅一次迁移） |
| WebGL 背景吃性能 | 高 | 全站仅 1 个 canvas + 离屏暂停 + 移动端降级 |
| 备案延期，域名一直不能指向国内机 | 中 | Vercel 长期托管作为兜底，随时可切 |
| 动效堆太多导致「炫但难读」 | 中 | 每条动效必须有语义（强调/引导/反馈），纯装饰动效限制在 Hero 一屏内 |
| bits 组件是复制进仓库的源码 | 低 | 集中放 `src/components/bits/` 并加来源注释，方便日后升级 |

## 8. 需要你拍板的三件事

1. **框架**：React（推荐）/ Vue / 其他
2. **主色与风格**：暗色 + 单一强调色（推荐，对齐你一贯的 dashboard 审美）/ 亮色极简 / 赛博霓虹
3. **Hero 要什么级别**：ogl shader（推荐，秒级惊艳、体积小）/ three.js R3F 3D（更炸但首屏 +150KB gzip）
