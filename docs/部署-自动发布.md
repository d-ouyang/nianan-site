# nianan-site 自动发布（打 tag → 自动构建 → 部署上线）

## 流程

```
git tag v0.9.0
git push origin main --tags
        │
        ▼
GitHub Actions（.github/workflows/deploy.yml）
  服务器 self-hosted runner 接单
  ① node:22-alpine 容器内构建（pnpm install + tsc -b && vite build）
  ② rsync dist/ → /var/www/personal（--delete 全量替换）
        │
        ▼
https://nianan.site 立即生效（静态产物无需 reload Caddy）
```

- 触发条件：**推送 `v*` tag**（平时 push main 不部署，与本项目「每个迭代打一个 tag」的节奏一致）。
- 另支持在 GitHub → Actions → deploy 页面手动触发（workflow_dispatch），用于重发同一版本。
- 并发守卫：同一时间只跑一个部署，新的排队会取消旧的。
- 构建在容器内完成，服务器宿主机不需要装 Node/pnpm；pnpm store 走 named volume 缓存，二次部署安装提速。

## 一次性激活（服务器上，只需做一次）

现有 runner 是注册给 `rag_qa_system` 的，**runner 只属于一个仓库**，
本仓库需要再注册一个（目录分开，不冲突）：

1. 浏览器打开：`nianan-site` 仓库 → **Settings → Actions → Runners → New self-hosted runner**，选 **Linux / x64**；
2. 页面会给出一组带临时 token 的命令，照抄执行，目录建议用 `/opt/actions-runner-site`：
   ```bash
   mkdir -p /opt/actions-runner-site && cd /opt/actions-runner-site
   curl -o actions-runner-linux-x64-<版本>.tar.gz -L https://github.com/actions/runner/releases/download/...   # 照抄页面上的
   tar xzf ./actions-runner-linux-x64-<版本>.tar.gz
   ./config.sh --url https://github.com/d-ouyang/nianan-site --token <页面上的TOKEN>
   # 交互问答：全部回车用默认值即可（runner group / 名字随便，labels 默认含 self-hosted）
   sudo ./svc.sh install
   sudo ./svc.sh start
   ```
3. 回到 Settings → Actions → Runners，看到新 runner 状态 **Idle** 即成功；
4. 验证：下一次打 tag 推送后，Actions 页应出现 deploy 运行且秒级被领走。

前置检查（沿用 rag_qa_system runner 的环境，一般都已满足）：
- runner 运行用户能执行 `docker`（rag 的部署已在用）；
- runner 运行用户对 `/var/www/personal` 有写权限。若 rsync 报权限拒绝，执行一次：
  `sudo chown -R $(whoami) /var/www/personal`。

## 状态监控

与 rag_qa_system 同款三看法：
1. GitHub 仓库 → Actions 标签页，绿勾=成功；
2. `gh run list -R d-ouyang/nianan-site --limit 3`；
3. 服务器 `ls -lt /var/www/personal | head` 看产物时间戳；`curl -s https://nianan.site | head` 看内容。

## 手动兜底

runner 不可用 / 紧急重发时，本地执行（效果与 CI 一致，带分支/工作区/落后检查）：

```bash
bash scripts/deploy-local.sh
```

需要指定服务器时：`DEPLOY_SERVER=ubuntu@42.192.111.82 bash scripts/deploy-local.sh`
